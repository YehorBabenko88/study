P0 — PASS
Защита выполняется parse_request до диспетчеризации любого маршрута.
Host: только точный loopback-host с реальным портом; чужой Host, неверный порт,
суффиксы DNS, дубли заголовка и absolute-form запросы отклоняются.
Origin: если присутствует, должен точно совпадать с origin текущего Host.
Все unsafe методы, включая POST/PUT/DELETE, PATCH и будущие методы/маршруты,
требуют непредсказуемый per-server X-Study-CSRF. Отсутствие Origin не даёт обход.
Bootstrap GET имеет no-store и не публикуется через CORS.
Это защита браузерной границы, не аутентификация от локального приложения.

Негативные проверки: hostile Host/Origin, null Origin, отсутствующий Origin,
нет токена, поддельный токен, same-origin без токена, unknown generation route.
Позитивные: same-origin + токен и native-клиент без Origin + токен.
Отдельно выполнены полные поддельные POST/PUT/DELETE с валидными payload:
число досок/PNG неизменно, защищаемая мнемоника сохраняется после каждого запроса.
На Windows раннее отклонение непрочитанного тела иногда даёт TCP reset вместо
читаемого 403. Это явно записано FULL_BODY_REJECTION; PASS требует проверки
отсутствия side effects, а не просто перехвата сетевой ошибки. Header-only
негативная матрица отдельно подтверждает 403 до чтения заявленного тела.

Study UI: общий wrapper добавляет токен только same-origin unsafe fetch;
реальный Chromium проверяет Request/body POST/PUT/DELETE и отсутствие утечки
токена на другой origin. Все legacy и новые UI E2E проходят с включённым gate.
