# Canvas UX Implementation Plan

> Execute inline with superpowers:executing-plans. User delegated design and implementation decisions.

**Goal:** Complete issue #9 without removing legacy features or breaking the five browser gestures.
**Architecture:** Extend the existing same-origin pointer bridge and canvas model. Keep gallery, recovery, keyboard and preview helpers in a dedicated browser script; persist only JSON board drafts, never image pixels. Server boards and assets remain authoritative and are never deleted by recovery.
**Tech Stack:** Vanilla JavaScript, Python HTTP server, Python unittest with Playwright Chromium.
**Spec:** GitHub issue #9 and the user's ten requirements.

## Constraints
- Base: docs/study-architecture-v0.1 at fdb540ffe63b4019cd95375b6806b0c8f455db29.
- Own branch agent-c/canvas-ux-drafts; Draft PR only, no merge/deploy.
- Preserve left-button dragging and existing IDs/API contracts.
- Existing open PR #11 explicitly avoids these UI files; no overlapping implementation found.

## Review focus
- Actual rendered bounds at non-unit scale and high DPI.
- Escape/pointer cancellation must leave model and history unchanged.
- Reload, malformed drafts, quota errors and competing tabs must not overwrite recoverable data.
- Gallery operations preserve card, order and assets across undo/redo and reload.
- Keyboard shortcuts must not intercept text editing.

## Tasks
- [ ] 1. Run baseline five browser tests. Add failing Playwright tests for exact bounds, gallery reorder/remove/history, draft recovery/corruption and pointer cancellation.
- [ ] 2. Implement DOM hit testing, gallery controls with pointer reorder and keyboard buttons, composition preview, transactional history and cancellable continuous drag previews. Run focused browser tests.
- [ ] 3. Implement versioned per-board local drafts, validation, recover/copy/keep options and storage conflict handling. Add keyboard navigation, transfer alternatives, fit and pan/zoom. Run extended browser tests including high-DPI/mobile contexts.
- [ ] 4. Run full unittest discovery and all browser cases, inspect screenshot, review changes independently, document exact evidence/limitations, commit/push and create/attach Draft PR.

## Decisions
- Use the fresh dedicated clone as isolation; no shared checkout changes.
- Recovery is explicit. A pending or invalid draft blocks autosave for its key until the user chooses how to proceed. Keep previous drafts as backups; local quota failures leave the current board intact.
- Preview is a separate action; legacy composeImages continues creating a composition immediately, preserving existing E2E behavior.
